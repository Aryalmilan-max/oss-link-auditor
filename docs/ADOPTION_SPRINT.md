# Evidence-first adoption sprint

The objective is two verified external uses and actionable maintainer feedback,
not a vanity star target. Public posts and direct outreach require human review
immediately before sending.

## Proof package

- [ ] README animation renders on GitHub
- [ ] deterministic demo passes from a fresh clone
- [ ] CodeQL completes without an open finding
- [ ] Marketplace page still shows the current release
- [ ] one separate public consumer repository runs the Action successfully

## Maintainer shortlist criteria

A candidate should meet all of these conditions:

1. The repository contains a substantial Markdown catalog, documentation tree,
   or curated resource list.
2. It has visible maintenance activity within the last six months.
3. The project does not already have an equivalent source-aware link workflow.
4. Its contribution or community rules allow a relevant tool suggestion.
5. There is a specific file or workflow where the audit would add value.

Do not contact repositories merely because they are popular. Record the exact
fit, maintainer rules, and proposed test before asking for feedback.

## Outreach sequence

1. Reproduce a useful result locally without modifying the target repository.
2. Save only non-sensitive counts and a minimal example.
3. Ask the maintainer whether the report is useful; do not ask for a star.
4. Offer an integration pull request only after they express interest.
5. Send no automated or repeated follow-up.

## Success threshold

The sprint succeeds when two independent maintainers either adopt the Action or
provide reproducible feedback that changes the roadmap. Stars, visitors, and
clones remain supporting metrics, not proof of adoption.
