# Seven-day launch plan

## Goal and guardrails

The goal is genuine maintainer adoption. Ten thousand stars in one week is an
aspirational viral outcome, not a forecast or guarantee. Never buy or exchange
stars, use bot accounts, automate unsolicited comments/DMs, or post where
self-promotion is prohibited.

## Audience and message

Primary users are maintainers of documentation, awesome lists, resource
catalogs, and Markdown knowledge bases. The core message:

> A redirect is not always success. OSS Link Auditor turns broken links,
> cross-host redirects, and blocked network targets into a source-aware report
> that leaves decisions with the maintainer.

## Schedule

### Day 1 — release foundation

- Merge the verified launch commit and confirm all CI jobs pass.
- Set the social preview, topics, description, website, and profile pin.
- Publish `v0.1.0` using the prepared release notes.
- Verify the Action in a separate public test repository.

### Day 2 — proof

- Run it on two maintained public resource lists with owner consent.
- Share only verified counts and link to reproducible evidence.
- Open three roadmap issues; label truly bounded tasks `good first issue`.

### Day 3 — developer launch

- Publish the Show HN draft after checking current community rules.
- Share in at most two directly relevant communities that permit projects.
- Respond technically to every genuine question; do not ask for stars.

### Day 4 — teach

- Publish “Why HTTP 200 is not enough for an awesome list.”
- Use verifiable examples for harmless, cross-host, and broken outcomes.
- Turn questions into FAQ/docs improvements.

### Day 5 — adoption sprint

- Invite 10-20 relevant maintainers individually to test a real workflow.
- Ask for feedback, not stars; disclose affiliation and avoid repeat contact.
- Offer a small integration PR only when invited.

### Day 6 — ship feedback

- Fix the highest-value confirmed issue and credit the reporter with consent.
- Release a tested patch if behavior changed.

### Day 7 — transparent recap

- Publish verified traffic, conversion, adoption, issue, and contributor data.
- Include what did not work. Choose the next feature from user evidence.

Every public post and outreach batch requires human review immediately before
publication. See [LAUNCH_CONTENT.md](LAUNCH_CONTENT.md) and
[LAUNCH_METRICS.md](LAUNCH_METRICS.md).
